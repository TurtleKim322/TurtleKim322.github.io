SAR 영상은 여러 위치에서 받은 반사 신호의 위상을 맞춰 합성한 결과다. 이 과정을 눈으로 확인하기 위해 Python으로 점 표적을 배치하고, 원시 신호 생성부터 영상 집속까지 실행했다. 실제 위성 데이터 대신 위치를 알고 있는 가상 표적을 쓰면 처리 결과가 제자리에 나타나는지 비교하기 쉽다.

이 글에서는 실행 환경, 처리 순서와 결과를 정리한다. 각 단계가 왜 필요한지는 [두 번째 글: 신호를 영상으로 만드는 수학](/sar-python/02-mathematics/)에서 식으로 살펴본다.

## 먼저 결과부터 보기

![왼쪽은 입력 점 표적 100개의 위치, 오른쪽은 같은 좌표 범위로 표시한 SAR 집속 영상](/assets/images/sar-python/01-targets-and-focus.png)

왼쪽은 입력한 점 표적 100개, 오른쪽은 신호 처리 후의 영상이다. 가로축은 플랫폼 진행 방향인 방위(azimuth), 세로축은 거리(range)다. 결과의 밝은 점들이 입력 분포를 따라 나타난다. 다만 가까운 표적들의 응답이 겹치므로 이 그림만으로 100개 모두를 정확히 분리했다고 판단하지는 않는다.

그림은 이번 시뮬레이션의 복소수 출력을 직접 그린 것이다. 색은 영상 전체의 최대 진폭을 0 dB로 둔 상대값이며, 비교하기 쉽도록 −45~0 dB를 표시했다. 보정된 후방산란 계수나 실제 지표 반사율을 뜻하지 않는다.

## 어떤 장면을 만들었나

플랫폼은 직선을 따라 일정한 속도로 이동하고, 표적은 움직이지 않는다고 가정했다. 표적은 진행 방향에 수직인 거리 좌표 5,000~5,050 m, 방위 좌표 0~50 m 안에 배치했다. 가장 가까이 지날 때의 거리를 기준으로 만든 2차원 모델이며, 지형고도와 입사각을 가진 실제 지상 지도는 아니다.

| 설정 | 값 | 의미 |
|---|---:|---|
| 반송파 주파수 | 10 GHz | 왕복 거리에 따른 위상 변화 결정 |
| 파장 | 0.03 m | 빛의 속도 3×10⁸ m/s로 계산 |
| 신호 대역폭 | 200 MHz | 거리 해상도 결정 |
| 펄스 길이 | 5 μs | 한 chirp의 시간 길이 |
| 수신 샘플링 주파수 | 250 MHz | 한 펄스 안의 시간 표본 간격 결정 |
| 플랫폼 속도 | 100 m/s | 펄스 사이 이동 거리 결정 |
| 방위 빔폭 | 3° | 한 표적을 관측하는 구간 결정 |
| PRF | 약 523.60 Hz | 1초에 송신하는 펄스 수 |
| 표적 | 100개, 난수 시드 0 | 반복 실행 시 동일한 위치 생성 |

거리 해상도의 이상적인 기준값은 0.75 m이고, 거리 **표본 간격**은 0.60 m다. 둘은 다른 값이다. 표본을 촘촘히 만든다고 두 표적을 구별하는 능력이 자동으로 좋아지는 것은 아니다. 또한 이번 처리에는 Hamming 창을 사용하므로 실제 주엽 폭을 0.75 m라고 그대로 단정할 수 없다.

## 실행 환경 만들기

검증에는 Windows와 Python 3.10을 사용했다. 라이브러리는 NumPy 2.2.6, SciPy 1.15.3, Matplotlib 3.10.7로 맞췄다. 기존 파이썬 환경에는 NumPy와 Matplotlib 사이의 호환 문제가 있어 이 프로젝트 전용 가상환경을 만들었다.

저장소 폴더에서 PowerShell로 다음 순서대로 실행한다.

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python SAR_python.py
```

가상환경을 따로 활성화하지 않고 그 안의 Python을 직접 실행하는 방식이다. 의존성을 다른 프로젝트와 분리하면서도 실행 경로를 분명하게 유지할 수 있다.

게시용 그림은 다음 명령으로 다시 만든다.

```powershell
.\.venv\Scripts\python make_figures.py
```

이 실행은 별도 그래프 창을 열지 않고 `results/`에 PNG 6개, 실행 로그, 수치 검증 기록을 저장한다. 난수 시드를 고정했으므로 같은 환경에서 같은 표적 장면을 재현할 수 있다.

## 원시 신호가 영상으로 바뀌는 순서

![표적과 플랫폼 이동에서 복소수 신호, 거리 압축, 방위 FFT와 RCMC, 방위 압축으로 이어지는 처리 순서](/assets/images/sar-python/03-processing-flow.png)

### 1. 표적까지의 거리로 복소수 신호 만들기

플랫폼 위치마다 각 표적까지의 거리를 다시 계산한다. 거리는 두 가지 방식으로 신호에 들어간다. 하나는 신호가 돌아오는 시간 지연이고, 다른 하나는 반송파의 위상이다. 빔 안에 있는 표적들의 반사 신호를 복소수로 더해 원시 데이터 배열을 만든다.

이 모델은 빔 안에서 동일한 반사 진폭을 사용하고 빔 밖의 표적은 제외한다. 실제 안테나의 부드러운 진폭 패턴, 거리 감쇠, 열잡음은 포함하지 않았다. 그래서 이 결과는 영상 형성 원리를 확인하기 위한 이상화된 실험이다.

### 2. 거리 압축으로 돌아온 시간을 구별하기

긴 chirp 신호에 대응하는 기준 신호로 상관 처리를 수행한다. 지연이 맞는 지점에서는 신호가 크게 합쳐지고, 다른 지점에서는 상대적으로 작아진다. 계산은 FFT, 기준 신호 스펙트럼의 켤레 곱, 역 FFT 순서로 수행한다.

![원시 반사 신호와 거리 압축 후 데이터 비교](/assets/images/sar-python/02-range-compression.png)

왼쪽 원시 신호는 한 표적의 에너지가 많은 수신 표본에 퍼져 있다. 오른쪽은 거리 압축 후 관심 거리 구간만 잘라낸 결과다. 두 패널은 세로 범위와 최대값 정규화가 각각 다르므로 색 밝기로 압축 이득을 비교하면 안 된다. 여기서는 거리 방향으로 응답이 모이는 형태를 본다.

원시 데이터의 세로축은 수신 표본 시간에 대응한 거리 좌표이고, 압축 후에는 기준 신호와의 상관 지연을 거리로 읽는다. 원본은 유한 길이 기준 chirp의 시작 표본을 배열에 넣는 방식이므로, 원시 패널의 넓은 띠를 표적 중심 거리로 직접 읽지 않는다.

### 3. 거리 이동 보정으로 같은 표적 정렬하기

플랫폼이 움직이면 같은 표적까지의 거리가 조금씩 변한다. 거리 압축을 했더라도 표적 응답이 여러 거리 셀을 지나갈 수 있다. 방위 방향 FFT를 수행한 뒤, 도플러 주파수별로 거리 축을 보간해 이를 보정한다. 이 단계가 RCMC(Range Cell Migration Correction)다.

### 4. 방위 압축으로 여러 펄스의 위상 맞추기

표적을 지나며 수신한 위상 변화에 맞는 기준 신호를 거리별로 만든다. 다시 상관 처리를 하면 방위 방향으로 퍼져 있던 에너지도 모인다. 거리와 방위 두 방향의 처리를 마친 결과가 첫 그림의 SAR 영상이다.

## 실행 결과를 어떻게 확인했나

기본 설정의 원시 데이터는 **2,083 × 1,642**, 최종 복소수 영상은 **251 × 4,096**이었다. 첫 번째 차원은 거리, 두 번째 차원은 방위다. 방위 영상 길이 4,096에는 FFT 처리를 위한 0 채우기 영역이 포함되어 있으므로 실제 송신 펄스 수와 같지 않다.

그림이 그럴듯하게 보이는 것만으로는 충분하지 않아 표적 하나만 따로 놓고 실행했다. 처리 수식은 유지하고 표적 위치만 거리 5,025 m, 방위 25 m로 바꿨다. 그 후 전체 영상에서 최대 진폭 위치를 찾아 입력 위치와 비교했다.

![단일 표적 영상과 최대점에서의 거리 및 방위 방향 단면](/assets/images/sar-python/06-single-target-check.png)

최대점은 거리 **5,025.000 m**, 방위 **25.005 m**에 나타났다. 위치 오차가 거리 표본 간격 0.60 m와 방위 표본 간격 약 0.191 m 이내임을 확인했다. 복소수 출력에 NaN이나 무한대가 없는지도 검사했다. 단면은 실제 표본을 연결한 것이며 추가 보간으로 더 높은 해상도를 얻었다고 해석하지 않는다.

입력 좌표와 비교할 때는 방위 축의 원점도 맞춰야 한다. 원본의 방위 축은 상관 기준 신호의 중심에 대한 상대 좌표다. 게시용 그림에서는 **중심 펄스의 플랫폼 위치를 더해** 입력 표적과 같은 방위 좌표로 표시했다. 영상의 복소수 값은 바꾸지 않았다.

이번 확인은 위치와 기본 실행의 검증이다. 전체 표적 검출률이나 실제 −3 dB 해상도, PSLR·ISLR까지 측정한 것은 아니다. 원본 마지막의 고정 영역 확대 그림도 단일 표적 검증으로 대신하지 않았다.

## 코드는 비공개로, 실험 기록은 블로그로

전체 소스와 실행 문서는 [비공개 GitHub 저장소](https://github.com/TurtleKim322/sar-python-simulator)에 보관한다. 이 링크는 소유자와 접근 권한이 있는 사용자만 열 수 있다. 이 블로그에는 실행 방법, 결과 그림과 수학 설명을 게시한다.

저장소를 정리할 때는 원본 실행 파일을 보존하고, 의존성 버전과 실행 안내, 그림 재생성 도구를 함께 넣었다. 가상환경, 캐시, 재생성 가능한 결과 폴더는 `.gitignore`로 제외했다. 저장소 생성 시 공개 범위를 **Private**으로 지정하고 업로드 후에도 비공개 상태를 확인하는 순서다.

블로그를 다시 수정할 때는 글과 사용한 PNG만 블로그 저장소에 반영한다. 코드 저장소가 비공개여도 블로그에 올린 그림과 설명은 공개된다는 점을 기준으로 게시 내용을 골랐다.
