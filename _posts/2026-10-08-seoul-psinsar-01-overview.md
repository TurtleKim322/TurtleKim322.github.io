서울의 지표 변화를 위성 레이더로 살펴보려면 한 장의 영상보다 여러 시기의 같은 산란점을 비교해야 한다. 이 프로젝트는 2020년부터 2025년까지의 Sentinel-1 자료를 이용해 PS-InSAR 처리 흐름을 구축하고, 실제 계산이 확인된 범위와 아직 검증이 필요한 단계를 분리해 기록한다. 이 글은 분석 질문, 데이터, 처리 환경과 해석의 경계를 먼저 정리한다.

## 무엇을 측정하는가

SAR는 지표에서 돌아온 레이더 신호의 진폭과 위상을 기록한다. 같은 위치를 다른 시기에 관측한 복소 SAR 신호를 결합하면 간섭 위상을 얻는다. 위상에는 지표의 위성 시선 방향(LOS) 이동뿐 아니라 지형 잔차, 대기 지연, 궤도 오차, 시간에 따른 산란 변화와 정합 오차가 섞인다. PS-InSAR는 여러 시기의 위상 이력을 사용해 비교적 안정된 산란점을 찾고, 이 오차 성분들을 다루며 시간에 따른 LOS 변화를 추정하는 방법이다. 따라서 “위상이 보인다”는 사실만으로 지표 침하를 결론내릴 수 없다. [StaMPS 방법 논문](https://doi.org/10.1029/2006JB004763)

이 작업의 질문은 서울 영역에서 장기간 비교 가능한 산란점과 신뢰할 수 있는 시계열을 만들 수 있는지다. 결과 해석에서는 관측 기하, 기준점, 대기 영향, 자료 공백과 후속 보정이 충분히 확인되어야 한다. 현재 공개 가능한 근거는 입력 정리, 후보점, 일부 patch의 StaMPS Step 1–3 진단까지다. 서울 전체 LOS 변위 지도나 검증된 침하 속도는 이 글의 결과로 제시하지 않는다.

## 데이터와 관측 기하

| 항목 | 프로젝트 기록 |
|---|---|
| 위성·제품 | Sentinel-1 IW SLC, 124개 획득 자료 |
| 관측 방향·궤도 | 상승(ascending), 상대궤도 127 |
| 기간 | 2020-01-04–2025-03-26 |
| 편파·처리 범위 | VV, IW2; burst 2–4가 기록된 처리 범위 |
| 기준 영상 | 2022-07-16 |
| 분석 AOI 기록 | 경도 126.75–127.20°, 위도 37.40–37.72° |
| 처리 환경 | SNAP 전처리, StaMPS, GNU Octave, WSL2 Ubuntu |

AOI 사각형과 실제 입력 영상의 footprint는 같은 의미가 아니다. 후보점 자료에는 AOI 바깥 좌표도 있으므로 공간 그림에서는 AOI 경계를 별도로 표시한다. 위성 궤도·상승 관측만으로 3차원 이동을 분리할 수도 없다. 결과를 지표의 수직 침하량으로 읽으려면 적절한 관측 조합과 기준 자료가 추가로 필요하다.

## 처리 흐름과 현재 증거

![서울 PS-InSAR 처리 흐름](/assets/images/insar-seoul/01-environment/pipeline-overview.png)

그림 1. **개념도.** SNAP에서 SLC 범위와 궤도를 준비하고, 영상 간 정합·간섭자료를 만든 뒤 StaMPS 입력과 후보점 처리로 이어지는 일반 흐름이다. 선으로 이어져 있어도 각 단계가 이 프로젝트에서 모두 검증되었다는 뜻은 아니다.

작업 폴더에는 20개 PATCH의 StaMPS 자료가 있다. P9와 P14의 실행 로그에는 Step 1–3 기록이 남아 있지만, 이는 해당 patch의 상태를 설명할 뿐 20개 PATCH 전체 완료나 최종 변위 산출을 입증하지 않는다. 자세한 산출물과 검증 경계는 각 글에서 파일 종류와 patch 이름을 함께 밝힌다.

SNAP과 StaMPS는 역할이 다르다. SNAP은 Sentinel-1 TOPS SLC의 영상 분리, 궤도 적용, 정합과 간섭자료 생성을 위한 전처리에 쓰이고 StaMPS는 여러 시기의 위상 이력에서 산란점 후보를 평가한다. 이 프로젝트는 StaMPS 스크립트 실행 환경으로 GNU Octave와 WSL2를 사용했다. MATLAB 전용 함수와 컴파일된 C 유틸리티, 대용량 행렬 입출력이 맞물려 있으므로 호환성과 자료형을 별도로 점검해야 했다.
