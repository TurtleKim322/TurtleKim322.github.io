“내용이 바뀌었다”는 목록만으로는 실제 검토가 끝나지 않는다. 긴 문서에서는 그 문장이 어느 페이지에 있는지 다시 찾아야 했다. Page View는 텍스트 비교 결과를 원본 지면 위로 돌려주는 화면이다.

## 페이지 번호만으로는 부족했다

PDF 텍스트를 읽을 때 페이지 번호와 bbox를 같이 저장한다. bbox는 페이지 좌표계의 사각형이다. 교차 형식에서 여러 블록을 합쳤다면 하나의 큰 사각형으로 억지로 덮지 않고 여러 페이지 영역을 보존할 수 있어야 한다.

좌우 페이지 번호도 항상 같지는 않다. 원본 2쪽 앞에 새 페이지가 생기면 대응은 수정본 3쪽일 수 있다. 비교 단계에서 모은 페이지 근거를 이용하고, Page View는 저장된 대응을 읽는다. 페이지를 누를 때마다 유사도 계산을 다시 하지 않는다.

## 원본 이미지와 표시 박스를 나누기

현재 화면은 QGraphicsView 기반이다. 지면은 QGraphicsPixmapItem, 변경은 별도 사각형 item이다. 원본 이미지에 색 박스를 직접 합성하지 않는다. 이렇게 해야 변경 박스를 켜고 끄거나 선택 항목을 바꿀 때 PDF를 다시 rasterize하지 않아도 된다.

| 변경 종류 | 표시 |
|---|---|
| 수정 | 황색 |
| 추가 | 녹색 |
| 삭제 | 적색 |

박스는 PDF point 좌표를 기준으로 둔다. 화면 확대는 view 변환으로 적용하고 PDF 회전 행렬도 반영한다. 0/90/180/270도 회전과 확대·캐시 경로는 회귀 테스트에서 확인했다. DPR=2 조건은 시뮬레이션했으며 모든 실제 모니터 조합을 검증한 것은 아니다.

## Word 지면은 Word에게 맡긴다

![직접 생성한 가상 서비스 제안서 PDF의 페이지 보기와 변경 박스](/assets/images/document-compare/03-page-view.png)

직접 만든 before/after PDF를 0.4.2 앱에서 비교한 Qt 화면이다. 계약 기간과 이용료를 바꾼 가상 예제이며 실제 업무 문서가 아니다.

DOCX 텍스트만으로 정확한 페이지 나눔을 복원하지 않는다. Word가 설치되어 있으면 읽기 전용으로 열어 임시 PDF를 생성하고, 텍스트와 확실히 대응하는 영역만 연결한다. HWP/HWPX 지면도 한컴 변환에 의존한다. 이미 PDF인 쪽은 다시 변환하지 않는다.

변환 PDF는 한 비교 안에서 재사용한다. 다만 첫 DOCX 페이지 보기에는 Word 시작과 변환 시간이 포함되어 수초가 들 수 있다. 한컴이 없으면 HWPX 텍스트 비교가 가능하더라도 그쪽 지면은 표시할 수 없다.

## 표시하지 않는 것도 결과의 일부

정확한 위치를 찾지 못하면 임의의 페이지나 사각형을 만들지 않는다. 텍스트 보기에서 검토하도록 안내한다. 현재 페이지에만 제한된 수의 박스를 생성하고, 전체 문서의 박스를 그래픽 객체로 미리 만들지 않는다.

이 화면은 이미지 차이 탐지기가 아니다. 텍스트 변경 위치를 PDF 위에 보여 주는 도구이므로, 그림만 바뀐 사례를 놓치는 한계가 있다. 지면을 보여 준다는 사실이 모든 시각적 변경을 검출한다는 뜻은 아니다.
