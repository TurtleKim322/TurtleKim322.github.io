비교 엔진이 차이를 찾아도 사용자가 다음 수정 위치로 이동하기 어렵다면 검토 시간이 줄지 않는다. UI에서는 기능을 더 넣기보다 원본과 수정본을 분명히 구분하고, 변경을 따라가며 원문을 확인하는 흐름을 정리했다.

## 파일 선택부터 결과까지

좌우 카드에 원본과 수정본을 고정하고 파일 선택과 Drag & Drop을 제공한다. 가운데 교환 버튼은 두 파일을 바꾸고 이전 결과를 지운다. 파일 하나를 제거하거나 전체 초기화를 했을 때도 오래된 결과가 새 파일의 결과처럼 남지 않게 했다.

파일을 열자마자 모든 UI를 새로 만드는 대신 비교 작업은 격리된 프로세스에서 실행한다. 진행 메시지를 보여 주고 취소 요청을 전달한다. 일정 시간 안에 끝나지 않는 작업은 작업 프로세스를 종료하는 경로가 있으며 GUI 스레드를 강제로 종료하지 않는다.

## 변경 목록과 문맥을 함께 보기

Change Navigator에는 추가·삭제·수정 항목이 모인다. 항목을 누르거나 이전/다음 변경으로 이동하면 같은 결과를 선택한다. Text View의 앞뒤 문맥은 변경 주변을 짧게 읽는 데 쓰고, 문서 전체 텍스트 검색은 다른 위치를 찾는 데 쓴다.

검색·종류 필터·변경만 보기는 역할이 다르다. 수정만 보도록 걸러도 비교 결과 자체를 다시 계산하는 것은 아니다. 화면에서 일부 항목을 숨긴 상태와 실제 문서에 변경이 없는 상태를 혼동하지 않도록 요약과 선택 상태를 유지한다.

## Text View와 Page View를 잇기

![가상 제안서의 텍스트 차이와 변경 탐색 목록](/assets/images/document-compare/02-text-view.png)

직접 생성한 예제만 사용해 렌더한 0.4.2 Qt 화면이다. 공개 이미지에는 로컬 사용자 경로나 최근 파일 목록을 포함하지 않았다.

텍스트 목록에서 선택한 변경을 페이지 좌표가 있는 경우 Page View에서도 따라간다. Page View에서는 파일 영역을 접어 지면 공간을 확보하고, splitter와 너비 맞춤을 제공한다. 좌우 확대와 스크롤 동기화도 켜고 끌 수 있다.

새 페이지를 읽는 동안 이전 화면을 유지할 때는 박스도 이전 페이지에 맞게 유지해야 한다. 새 페이지 번호에 옛 이미지를 붙이거나, 새 박스를 옛 지면 위에 올리는 중간 상태는 피했다. 결과가 도착하면 지면과 그 위치 정보를 함께 바꾼다.

## 한 번에 모두 표시하지 않기

Text View는 30문단 단위의 창으로 결과를 읽는다. 수만 문단을 거대한 HTML 문자열로 만들어 한 번에 넣지 않는다. Page View도 현재 페이지 쌍 중심이다. 화면 밖 모든 페이지의 widget을 만드는 연속 스크롤 모드는 현재 구현 범위에 없다.

이런 제한은 검토 내용을 없애는 것이 아니라 화면에 필요한 만큼만 꺼내는 선택이다. 전체 텍스트 검색과 이전/다음 변경이 그 사이를 연결한다. 대용량 안정성과 UI 응답성이 별개의 작업이 아니라는 점을 이 단계에서 확인했다.
